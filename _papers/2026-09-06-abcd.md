## 一句话总结

ABCD 把 alpha-composited radiance field 的训练重写为空间 block coordinate descent：当前 cell 的 Gaussian 与 optimizer 留在 GPU，其他 cells 冻结并按每个训练相机折叠成一个 background 与一个 foreground RGBA 层，于是活动块仍能在“看见完整场景上下文”的图像上获得梯度，而训练 VRAM 不再随总 cell 数增长；它解决的是**训练装不下**，不是让最终大模型的存储、评测或实时渲染也自动变成常数显存。

## 背景与动机

- **3DGS 的训练内存随场景规模增长**：Gaussian 的 position、covariance、opacity、SH、梯度统计与 Adam state 通常同时驻留 GPU。场景范围和 primitive 数上升后，单卡先被模型/optimizer 撑满。
- **最直接的分块独训会丢失上下文**：一个训练相机通常同时看见多个空间块。如果每块只对完整目标图像独立拟合，它会把其他块的颜色与遮挡也错误解释为自己的责任，合并后出现边界、重复几何与颜色不一致。
- **已有 large-scale 方法常依赖更强假设**：Mega-NeRF、NeRF-XL 使用多 GPU 或区域分解；BlockGaussian 加 overlap/边界处理；A LOD of Gaussians 使用 3DGS-specific LOD tree。它们有效，但可能依赖分区质量、表示类型或昂贵硬件。
- **alpha compositing 有可复用的结合律**：冻结层的颜色和透明度不需要以全部 primitives 形式参与每一步。只要相对活动凸区域的前后顺序固定，它们可以先合成成两张图，再与活动块 render 组合。
- **作者切入点**：把稀缺 GPU 只留给一个可训练 parameter block，把冻结模型搬到磁盘/CPU，并将其对当前 block 有用的信息压缩为 image-space sufficient context。

**核心研究问题：能否让一个空间块像在完整 radiance field 中一样接受遮挡与颜色监督，同时完全不把其他块的参数和 optimizer state 放入 GPU？**

## 核心问题

1. **如何避免独立块“拟合别人负责的像素”？** 活动块必须知道它前后已有多少颜色和 opacity，而不只是看到原始 target。
2. **冻结块能否被压成固定大小的上下文？** 需要利用 alpha compositing 的 associativity，将任意数量的 inactive blocks 压成前、后两层。
3. **如何确定每个块相对活动块的前后顺序？** 理论需要固定 global ordering，实际大 covariance、相交投影和宽视角会破坏简单 cell-level 排序。
4. **如何在 block 间轮换 densification、optimizer state 和 cache？** 不仅模型参数，Adam moments、训练 iteration 与 camera render snapshots 都必须可保存和恢复。
5. **所谓 constant VRAM 的条件是什么？** partition volume、Gaussian density、image resolution 和单步 camera working set都必须受限；磁盘、RAM、camera 数与运行时间并非常数。

## 方法详解

### 整体流程

论文配置用边长 5 的 regular cubes。当前代码按 cell 顺序循环，每个 cell 连续更新 `sync_interval=250` 次，然后切换；重复轮转，直到**每个非空 cell**各自达到 5000 iterations。最终所有 shards 合并为标准 3DGS PLY。

### 1. 从全模型优化改写为 Block Coordinate Descent

把场景参数写为：

$$
\Theta=\{\theta_1,\theta_2,\ldots,\theta_K\},
$$

其中 $\theta_i$ 是空间 partition $P_i$ 内的 Gaussian 参数。一次 block update 只优化：

$$
\theta_i\leftarrow
\theta_i-\eta\,
\nabla_{\theta_i}
\mathcal L\bigl(\theta_i;\Theta_{-i}\text{ frozen}\bigr).
$$

普通 block coordinate descent 仍可能需要完整 $\Theta$ 做 forward。ABCD 的关键是把 $\Theta_{-i}$ 对当前相机的影响预积分成图像，因而 GPU 不需要冻结参数本身。

代码不仅保存每块 Gaussian tensors，也保存：

- 当前 local iteration 与 active SH degree；
- Adam optimizer state；
- densification 是否因 memory/count 停止；
- 每个 cell-camera 的 RGB/depth/alpha snapshot。

因此 block switch 不是重新初始化优化器，而是暂停并恢复该 shard 的局部优化轨迹。

### 2. Alpha compositing associativity：把 inactive blocks 折叠成两层

对前层 $X_f=(C_f,\alpha_f)$ 和后层 $X_b=(C_b,\alpha_b)$，标准 `over` 运算可写为：

$$
C_{f\operatorname{over}b}
=\alpha_f C_f+(1-\alpha_f)C_b,
$$

$$
\alpha_{f\operatorname{over}b}
=\alpha_f+(1-\alpha_f)\alpha_b.
$$

该运算满足结合律，所以一串冻结 layers 可以预先合成为单个 layer。若活动 convex partition 前后的集合分别为 $\Theta_{fg}$、$\Theta_{bg}$，则：

$$
\hat I(\theta_i)
=F_i\operatorname{over}
\left[
A_i(\theta_i)\operatorname{over}B_i
\right],
$$

其中 $F_i$ 和 $B_i$ 分别是冻结 foreground/background 的扁平 RGBA 图，$A_i$ 是当前活动块 render。

直觉是：背景先被活动块挡住，再一起被前景挡住。$F_i,B_i$ 是常量，autograd 只需穿过 $A_i(\theta_i)$；但活动块看到的残差仍来自完整合成结果，不会像独立分块那样把前后区域都吸收到自己内部。

#### “等价”成立的条件

论文所说的等价依赖：

1. 活动 partition 是 convex；
2. 对该相机，每个 inactive primitive/layer 能被明确归为整体在活动区前或后；
3. layer 顺序正确且固定；
4. cached render 精确表示冻结参数当前状态；
5. 使用同一种 alpha compositing 语义。

在这些条件下，先合成 inactive layers 和每步显式渲染它们得到相同结果。ABCD 的工程实现只能近似这些条件，后文会单独讨论。

### 3. Camera–cell visibility 与前后景排序

代码先用 camera frustum 与 cell axis-aligned bounding box 相交测试，建立：

- camera → visible cells；
- cell → cameras that observe it。

训练一个 cell 时只采样能看到它的 cameras。对每个 camera，代码用 cell center 沿 camera `look_at` 的投影距离：

$$
d(P_i,c)=
\left\langle
\operatorname{center}(P_i)-o_c,\;v_c
\right\rangle
$$

给 cells 排序；比 active center 更近的归 foreground，更远的归 background，再分别 alpha-composite。

这个方案是 cell-level depth approximation，而不是逐 pixel 或逐 Gaussian 精确排序。它便宜，但两个 spatial cubes 在相机视锥内深度范围重叠时，不一定存在全局顺序。README 明确将其列为限制。

### 4. Cache 与三层内存层级

官方 README 将存储分成：

```text
disk -> inactive partition checkpoints + cached renders
RAM  -> 当前 block 的 camera context / 可选 RAM cache
VRAM -> one active partition + optimizer + one camera working set
```

当前 disk cache 对每个可见 cell-camera snapshot 存：

| 内容 | 精度 | 作用 |
| --- | --- | --- |
| RGB | `uint8` | frozen block 的颜色贡献 |
| alpha | `uint8` | frozen block 的遮挡贡献 |
| depth | `float16` | 合成与可视化/排序上下文 |
| inactive Gaussian + optimizer | tensor checkpoint on CPU/disk | block resume |

文件先写 `.tmp`、flush/fsync，再 atomic replace；metadata 保存 size、SHA-256、cache format version 和 training-config fingerprint。`--resume` 只接受 fingerprint 相同且 checksum 通过的 shards。RAM mode 避免 block-switch I/O，但进程退出即丢失、不能 resume，且 host RAM 随总场景增长。

当前训练入口把 precomposited foreground/background layers 放在 CPU；每步为采样 camera 把相应 pair 传到 GPU。因此 GPU working set 可以保持一对图，但 active cell 切换时需要为可见 cameras 读取、排序并预合成上下文。

### 5. Block switching、cache freshness 与训练日程

每次激活 cell 的顺序是：

1. 将上一个 cell model/optimizer 搬到 CPU 并写 shard；
2. 从 disk/RAM 恢复新 cell 到 CUDA；
3. 为所有能看见该 cell 的 cameras，把其他已有 snapshots 折叠成 $F/B$；
4. 在这些 cameras 上运行 250 次 MSE update；
5. 本轮结束后，把 mean 约束在 cell bounding box 内，删除越界 ownership，并重渲染该 cell 的 camera cache；
6. 清除该 cell 更旧的 render snapshots，切到下一 cell。

首次 sweep 时，尚未训练、`current_iter=0` 的 cells 没有 cache，会被忽略；随着轮转进行，场景上下文逐渐完整。默认 `extra_cell_compensation="last"` 使用每个 inactive cell 各自最新 snapshot，不要求所有 cells 来自同一个 global iteration。因此它更接近带 stale/delayed context 的 cyclic block optimization，而不是每轮都对同一全局模型快照做精确 BCD。

### 6. 3DGS 优化、densification 与边界约束

ABCD 与 baseline 复用同一个 basic trainer：

- Adam，原始 3DGS 风格的 parameter-group learning rates；
- SH degree 每 1000 local iterations 提升；
- 500 local iterations 后每 100 iterations densify/prune；
- opacity 每 3000 iterations reset；
- 每次 optimizer step 后将 Gaussian means clamp 在当前 cell 内；
- 每个 sync chunk 后再次按 bounding box mask 清理。

一个重要源码事实是，当前 trainer 为速度只使用：

$$
\mathcal L_{\text{image}}=
\|\hat I-I_{gt}\|_2^2,
$$

即 MSE；原版 3DGS 常见的 $L_1+$D-SSIM 在此实现中没有使用。论文三种方法均走同一代码路径，因此内部比较仍一致，但结果不应直接与标准 30k-iteration GraphDECO 指标横比。

空间归属按 **Gaussian mean** 决定。虽然 mean 被限制在 cell 内，anisotropic covariance/support 可以跨越边界；这会破坏“整个 primitive 严格在 partition 内”的假设。

### 7. 训练结束与推理边界

训练结束时，`grid_merge()` 会加载全部 cells 到 host memory、合并为一个标准 `model.ply`。官方 `abcd-evaluate` 默认：

```python
GaussianModel.from_ply(..., device="cuda")
```

也就是把**完整合并模型**加载到 GPU 评测。ABCD 当前解决的是 training residency，不是 final model compression、out-of-core inference 或 LOD rendering。若大场景最终 PLY 仍放不进 GPU，还需要另一个 rendering/streaming 系统。

## 显存复杂度到底是什么意思

对常规 3DGS，可粗略写为：

$$
M_{\text{3DGS}}
=O(G_{\text{total}})+O(HW),
$$

$G_{\text{total}}$ 包含模型、梯度、optimizer 与 densification statistics。ABCD 的单步 GPU working set 为：

$$
M_{\text{ABCD}}
=O(G_{\text{cell}})+O(HW),
$$

其中 image term 包括活动 render 和 foreground/background pair。若满足：

- partition physical volume 固定；
- 单位体积 expected Gaussian density 有界；
- image resolution 固定；
- 每步只流式加载一个 camera pair；

则扩大场景只增加 disk/CPU 中的 blocks，不增加 peak training VRAM，因而相对于 total scene extent 是 $O(1)$。

这不是“所有资源 O(1)”：

- disk cache 随 visible cell-camera pairs 和分辨率增长；
- current implementation 在 block switch 时的 CPU context 可随 visible cameras 增长；
- runtime 随 cells、cache I/O 和总更新数增长；
- 一个极高密度 cell 仍可使 $G_{\text{cell}}$ 爆炸；
- final merge/evaluation 仍处理完整模型。

官方 `abcd-memory` command 也只固定 active shard 为 128 Gaussians，构造 1/2/4/8 个 partitions，检查 inactive shards 增加时 `max_memory_allocated` 的 spread 是否低于 1 MiB。它验证的是**inactive shard 不驻留 CUDA**，没有覆盖完整 rasterization、image pairs、optimizer、camera 数或真实大场景训练峰值。

## 实验关键数据

### 实验设置

论文只评估两个场景：`garden` 与 `kitchen`。正文称其来自 original NeRF dataset，但场景名称、README 和下载脚本将其明确为 **Mip-NeRF 360** resized dataset；这是正文表述与仓库之间的小不一致。

- 输入：`images_4` 与 COLMAP sparse reconstruction；
- 每第 8 个 camera held out，约 200 training cameras/scene；
- regular grid side length：5 scene units；
- methods：完整 3DGS、分块但无 compositing、完整 ABCD；
- budget：3DGS 对全模型做 5000 iterations；两个 partitioned methods 则让每个 cell 各做 5000 local iterations，每 250 updates 切块；
- 指标：论文报告 held-out PSNR、SSIM，以及 peak VRAM、system RAM、wall time；当前 evaluator 也实现 LPIPS，但 Table 1 未报告。

需要注意，三种方法不是相同总 optimizer-step 数：源码显示 ABCD 是“5000 steps per cell”，baseline 是“5000 steps total on full model”。这反映各自训练定义，但不是 compute-matched comparison，也是 ABCD runtime 增长的重要来源之一。

### 主结果

| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Garden | 3DGS | 0.88 | 7.88 | 99.6 | 24.01 | 0.596 |
| Garden | ABCD no comp. | **0.69** | 8.98 | 402.7 | 16.56 | 0.356 |
| Garden | ABCD | 0.80 | 25.02 | 1081.3 | 23.65 | 0.575 |
| Kitchen | 3DGS | 0.97 | 3.73 | 67.4 | 27.03 | 0.861 |
| Kitchen | ABCD no comp. | **0.75** | 5.60 | 441.3 | 15.64 | 0.504 |
| Kitchen | ABCD | **0.77** | 17.73 | 1041.0 | 25.80 | 0.839 |

两场景平均：

| Method | VRAM GB ↓ | RAM GB ↓ | Time s ↓ | PSNR ↑ | SSIM ↑ |
| --- | ---: | ---: | ---: | ---: | ---: |
| 3DGS | 0.925 | 5.805 | 83.5 | 25.52 | 0.7285 |
| ABCD no comp. | **0.720** | 7.290 | 422.0 | 16.10 | 0.4300 |
| ABCD | 0.785 | 21.375 | 1061.2 | 24.73 | 0.7070 |

### 如何解读这些数字

1. **Compositing 是质量恢复的关键**：分块但无上下文相对 3DGS 平均下降 9.42 dB；加入 $F/B$ 后只差 **0.79 dB**。作者按 dB 数值比例称 PSNR degradation 从 36.9% 降到 3.1%，但 PSNR 是对数单位，更建议报告绝对 dB 差。
2. **实际 VRAM 节省有限**：ABCD 平均 0.785 GB，相比 3DGS 0.925 GB 只低 **15.1%**；no-compositing 为 0.720 GB。ABCD 为上下文只增加约 65 MB，说明 compositing 没破坏 partition residency，但小场景不足以展示巨大收益。
3. **资源转移非常明显**：ABCD 的 RAM 为 21.38 GB，是 baseline 5.81 GB 的约 **3.68×**；这符合“用便宜 storage tiers 换 GPU”的设计，却不能描述成整体 memory reduction。
4. **时间代价很高**：ABCD 平均 1061.2 s，是 3DGS 83.5 s 的约 **12.7×**，也是 no-compositing 的约 2.51×。来源包括更多 total local steps、cache 生成/读取、block switches 与小 active shard 的低 rasterizer occupancy。
5. **Kitchen 的质量损失更明显**：Garden 只降 0.36 dB，Kitchen 降 1.23 dB，说明当前分区/排序近似对场景结构敏感；只有两个样本，无法判断分布。

### 唯一核心消融：去掉 compositing

`ABCD no comp.` 保留分块 residency，却只渲染 active cell 对完整 target 拟合。它的 VRAM 与完整 ABCD 很接近，但 PSNR/SSIM 崩溃，直接证明：

- 低显存来自 block residency；
- 恢复质量来自 frozen context；
- 仅仅“训练完再 merge”不能解决跨 partition 相机监督冲突。

但论文没有消融 partition size、sync interval、cache precision、center-depth ordering、disk/RAM mode、visibility threshold、staleness 或 overlap，因此无法知道质量/速度对这些关键旋钮的敏感性。

### 训练动态与活跃 Gaussian 数

Figure 3 显示完整 ABCD 的 loss trajectory 接近 3DGS，而 no-compositing 明显更差；ABCD 与 no-compositing 的 active Gaussian residency 近似，支持“foreground/background images 恢复质量而不恢复全模型驻留”的解释。

图没有提供足够坐标值来重建完整曲线，也没有报告 total Gaussian counts、cells 数、disk cache 体积或 I/O bandwidth。本笔记不从图形外推未给出的具体数值。

## 数学思想与工程实现之间的差距

论文的核心推理是成立的，但当前实现不是严格等价 full-scene rendering：

1. **Mean-based ownership**：Gaussian covariance 可以跨 cell boundary；
2. **Center-depth ordering**：用 cube center 代表整块，无法处理 block 投影深度交错；
3. **Quantized cache**：RGB/alpha 为 uint8、depth 为 float16，不是 lossless frozen render；
4. **Stale snapshots**：每块使用各自最后一次更新后的 cache，不是统一 global iteration；
5. **Dynamic parameter dimension**：densification/pruning 让每个 block 的变量数随训练变化，超出最简单的固定维 BCD 分析；
6. **初始 context 不完整**：first sweep 时尚未训练的 cells 没有 snapshot，会被忽略。

这些近似并不否定方法，而是解释了为何 ABCD 仍比 3DGS 低 0.79 dB，也说明理论 convergence 不能仅靠“coordinate descent 通常收敛”带过。

## 官方代码核对

### 值得肯定的工程点

- 提供 `abcd-train`、`abcd-evaluate`、`abcd-reproduce`、`abcd-memory` 等完整 CLI；
- `run.json` 记录 git revision、GPU、Torch/CUDA、camera split 与全部训练配置；
- disk cache 和 shards 使用版本号、fingerprint、atomic write 与 SHA-256；
- resume 同时恢复 model、optimizer、local iteration、SH degree 和 densification state；
- disk/RAM 两种 cache 模式明确区分可恢复性与速度；
- tests 按 compositing、geometry、GPU、I/O、trainers 等模块组织；
- Viser + OpenCV live viewer 可以观察 active block 和完整合成结果。

### 需要谨慎理解的实现边界

- 原创 ABCD Python code 是 MIT，但 vendored GraphDECO rasterizer/simple-knn 仍受 research/evaluation-only 条款限制，整个仓库不能简单视为无条件商业 MIT；
- memory command 不等于端到端 benchmark；
- paper reproduction 默认仅两个小 scenes 和 5000 local iterations；
- final evaluator 把完整 PLY 加载到 CUDA，未验证大模型 inference；
- 当前 default disk cache 改善 host RAM/可恢复性，但论文 Table 1 的高 RAM 与 runtime 仍表明 image context 不是免费的。

## 亮点与洞察

### 论文亮点

- **找到 alpha compositing 的 sufficient statistic**：对当前 block 而言，冻结场景不必保留 primitive-level 细节，只需提供前后两张 RGBA。这是比“把模型移到 CPU 再逐个 render”更本质的压缩。
- **把 block coordinate descent 变成 representation-aware system**：算法利用 radiance field 的 compositing algebra，而不是把通用 optimizer 生硬套到 3DGS。
- **分清 memory mechanism 与 quality mechanism**：no-compositing 消融很好地说明前者来自 partitioning，后者来自 cached context。
- **目标取舍诚实**：论文承认实际小场景 savings 被固定 overhead 掩盖，也明确报告 RAM 和 runtime 大幅增加，没有只展示 VRAM。
- **代码比 Poster 论文更可用**：cache consistency、resume、reproduction 和 viewer 对真正跑 out-of-core 任务很重要。

### 我的洞察

1. **ABCD 本质是“把 frozen 3D state 投影成 active block 的 2D boundary condition”**。它与 domain decomposition 中交换边界条件相似，只是消息不是几何参数，而是每相机 RGBA。
2. **Associativity 解决“怎么压缩”，ordering 决定“压得对不对”**。真正的薄弱点不是 alpha 公式，而是能否把 inactive content 稳定分成 active 前后。复杂户外视锥下 center-depth 排序可能比论文篇幅暗示的更关键。
3. **它把扩展维度从 scene size 改成 view-conditioned cache size**。GPU 与 $G_{total}$ 解耦，但 camera count、resolution、visibility density 会进入 disk/RAM/I/O；这是资源维度迁移，不是消失。
4. **sync interval 是 stale-context 与 I/O 的核心旋钮**。更频繁切换让 context 更新及时，却增加 disk traffic；更久停留提高 amortization，却用更旧的其他 blocks 优化。论文没有给出这条曲线。
5. **ABCD 与 LOD/compression 是互补关系**。前者控制训练时 active parameters，后者减少每块 primitive/bit 数；两者结合可能同时降低 GPU、disk cache 与最终 inference 压力。
6. **当前 12.7× 时间不能简单归因于算法必然慢**。源码的 per-cell 5000 steps 使总 step 数随 cells 增长，且小 shards 低 occupancy；应在相同 wall time、相同 total rasterized primitives 或相同 quality 下画 memory–time–quality Pareto。

## 局限与展望

### 作者明确承认的限制

- 只评估了 Gaussian 数较少的小场景，optimizer/image/rasterization overhead 掩盖渐近优势；
- 没有充分调优 densification 与 training hyperparameters；
- 一个 active partition 可能被许多 cameras 看见，仅 frustum culling 时 cache 数仍随场景增长；
- 缺少 visibility threshold 与 dynamic occlusion culling；
- Gaussian mean 属于 cell 不代表 covariance support 不跨界；
- center-level depth ordering 是近似；
- Gaussian Splatting 下的 BCD convergence 仍是开放问题；
- 当前实现只有单 CUDA GPU；
- 尚未在真正 ultra-large real-world scenes 上验证。

### 独立分析

1. **核心 claim 主要是架构/渐近论证，不是大规模实证**：Table 1 反而显示 VRAM 绝对差只有 0.14 GB；论文题目中的“large radiance fields”没有被 large-scene experiment 支撑。
2. **样本量不足**：两个 Mip-NeRF 360 scenes，没有重复 seeds、error bars 或统计显著性；Garden/Kitchen 也不能代表 aerial、city-scale、long trajectory 或 high-density captures。
3. **比较预算不统一**：每 cell 5000 steps 与 baseline 总计 5000 steps 导致 wall-time/step 不可直接归因。需要 quality-matched 或 compute-matched curves。
4. **没有 disk footprint**：方法把显存压力转成 render cache，但论文未报告 cache GB、读写量、switch latency、SSD 类型或耐久性。
5. **没有峰值分解**：表格未区分 parameters、optimizer、images、precomposites 和 rasterizer temporary buffers，无法验证哪个项会在大场景真正主导。
6. **只解决训练，不解决部署**：最终 merged PLY 和 evaluator 仍是 full-model CUDA path；大场景可能训练得出来却渲染不了。
7. **相机相关 cache 可能成为新瓶颈**：如果每个 cell 被大量 views 看见，$O(KC_{visible}HW)$ storage 会很大；“远块可以忽略”目前是未来工作，不是已有策略。
8. **“任意 alpha-composited radiance fields”仍未实证**：论文只实例化 3DGS。NeRF ray sampling、dynamic scenes、anti-aliasing 或 learned compositors 是否同样适用尚未展示。

### 最值得补做的实验

- 在至少一个 full-resolution city/aerial/large indoor capture 上展示 conventional 3DGS OOM、ABCD 成功；
- 扫描 cell size × sync interval，报告 PSNR、VRAM、RAM、disk、I/O、wall time Pareto；
- 比较 center-depth、per-pixel depth intervals、overlapping cells 与 covariance-aware assignment；
- 分别使用 lossless float cache、uint8/float16 cache，量化其质量/存储影响；
- 报告 cold-start、first sweep 和 steady-state loss，测 stale cache 的影响；
- 在 equal total updates、equal wall time 与 equal PSNR 三种协议下比较；
- 将 final rendering 也做 block/LOD streaming，验证 end-to-end large-scene workflow；
- 在 NeRF 或其他 alpha-composited representation 上给出第二个实例，支撑方法通用性。

## 与相关工作的对比

| 方法 | 扩展方式 | 跨块上下文 | 主要资源 | 与 ABCD 的差异 |
| --- | --- | --- | --- | --- |
| 独立 partition–train–merge | 每块完全独训 | 无 | 单块 GPU | 最简单，但每块会补偿缺失内容；ABCD no-comp 已证实质量崩溃 |
| Mega-NeRF | 区域化 NeRF experts | overlap / gating | 多模型与分区训练 | 面向 large NeRF，分解设计更强；ABCD 用通用 alpha context 减弱独训冲突 |
| NeRF-XL | 多 GPU distributed NeRF | 跨设备协调 | 多 GPU / 通信 | 可扩大模型但硬件昂贵；ABCD 目标是单卡 out-of-core |
| BlockGaussian | adaptive block-based 3DGS | overlap / auxiliary boundary handling | block models | 依赖 partition strategy；ABCD 把 inactive blocks 渲染成上下文 |
| A LOD of Gaussians | external-memory LOD hierarchy | hierarchy/LOD selection | CPU/disk + level selection | 同时服务 ultra-large training/rendering，3DGS-specific；ABCD algebra 更通用但当前只覆盖训练 |

ABCD 不是这些方法的完全替代品。更现实的方向是：用 overlap/LOD 改善 ordering 与 block density，再用 alpha-composited BCD 限制训练 active working set。

## 启发与关联

- **对大规模 3DGS**：可以把每个 spatial shard 看成 actor，只交换 view-conditioned RGBA messages；分布式版本不必频繁同步全部 Gaussian tensors。
- **对动态场景**：可按 space-time blocks 训练，但 frozen cache 会因时间变化失效；需要 temporal validity 和 motion-aware ordering，这是未经验证的假设。
- **对 SLAM/增量建图**：固定旧地图，把其 render 缓存作为新区域优化的前后景条件，可能减少历史 map 常驻 GPU；相机持续增加时 cache 管理会成为关键。
- **对 inverse rendering**：若各块还预测 material/light，单一 RGBA 未必是充分上下文；可能需要额外 visibility、normal 或 transport buffers。
- **对系统设计**：ABCD 提醒我们，out-of-core 的关键常不是简单 parameter swapping，而是寻找对当前 optimization block 足够的低维 frozen-context representation。

**综合：7.1/10，值得选择性细读。** 这是一个很好的 systems idea 与 research prototype，尤其适合思考“如何把 3D frozen context 压成局部优化所需信息”；但在出现真正大场景、端到端 memory–time–quality 曲线前，还不能视为已证明的 large-scale 3DGS 训练方案。

## 阅读结论

- **最值得记住的点**：ABCD 不是把其他 blocks 简单搬到 CPU，而是把它们对当前 block 的作用压成 $F\operatorname{over}(A\operatorname{over}B)$ 两张 RGBA boundary conditions，因此只对 active cell 反传仍能看到完整图像残差。
- **最需要怀疑的点**：标题强调 constant VRAM/large scene，但主实验只省 15.1% VRAM，且没有大场景；数学等价还被 center ordering、mean ownership、quantization 和 stale cache 近似削弱。
- **最值得复现或继续验证的点**：在 conventional 3DGS 确实 OOM 的场景上，同时记录 VRAM、RAM、disk、I/O、总 updates、wall time 与 held-out quality，并把 out-of-core 机制延伸到最终渲染。
