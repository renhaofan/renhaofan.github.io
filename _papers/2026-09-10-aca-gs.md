> **术语说明**：文中的 **anchor** 是稀疏、可共享特征的结构节点；每个 anchor 由 MLP 解码出多个局部 **Neural Gaussians**。ACA-GS 压缩的是整套动态 radiance-field 表示，而不只是最终 rasterizer 中可见的 Gaussian 数量。

## 一句话总结

ACA-GS 将锚点式动态 Gaussian 的“每个 anchor 固定生成 $K$ 个 Gaussians、固定使用 $C_F$ 维特征”改成按局部时空复杂度分配容量：Adaptive Anchor Cardinality（AAC）回收低 opacity 贡献的 Neural Gaussians并迁移到高重要性 anchor，Adaptive Anchor Feature Masking（AAFM）让简单区域只保留基础特征块、复杂或高运动区域使用完整特征；结合 GIFStream 的熵编码后，模型以轻微感知质量交换约 35%–42% 的额外存储缩减。

## 背景与动机

- **动态 3DGS 的基本矛盾**：deformation-based 方法用 canonical Gaussians 加变形网络，存储较省，但快速、大幅或拓扑变化的运动难拟合；4D primitive-based 方法表达力更强，却会让参数沿时间维膨胀。
- **Anchor representation 是折中方案**：Scaffold-GS 以稀疏 anchor 共享 feature，再按视角生成局部 Neural Gaussians；GIFStream 将它扩展到动态场景，并对 anchor attributes 与 temporal feature stream 做端到端压缩。
- **现有 anchor 容量是均匀的**：每个 anchor 拥有同样数量的 Gaussian offsets 与同样维度的 feature，无论它覆盖的是平滑背景、精细静态纹理还是快速运动区域。
- **固定容量导致两种浪费**：复杂静态区域为获得更多 Gaussians 只能继续 densify anchors；简单区域则保留不需要的 Gaussians 和 feature channels。
- **运动表示与空间细节耦合**：anchor-level deformation 需要在高速运动区域布置较密 anchors；如果每个 anchor 又固定附带多个 Gaussians 和完整空间特征，会为“增加运动自由度”额外支付不必要的空间容量。

作者的核心观察是：**anchor density、per-anchor Gaussian cardinality 和 anchor feature capacity 是三个不同的资源轴，不应全部通过 densification 一项操作解决。**

**核心研究问题：能否在不增加 anchor 数量的前提下，把无效 Gaussian 和无效 feature capacity 重新分配给真正复杂的时空区域，从而改善动态 3DGS 的 rate–distortion？**

## 核心问题

1. Anchor-based 方法的 Gaussian opacity 是按视角临时解码的，如何得到跨相机、跨时间较稳定的 primitive importance？
2. 如何改变每个 anchor 的有效 Gaussian 数，而不为不同 cardinality 建立不同 MLP、破坏 batch parallelism？
3. 如何删除冗余 anchor features，同时避免 temporal feature 被迫承担丢失的空间细节？
4. 自适应结构本身与 GIFStream 熵编码分别贡献多少存储缩减、质量和速度收益？
5. 轻微 PSNR/LPIPS 损失是否足以支持“without degrading visual quality”的强表述？

基线为 GIFStream 风格的 anchor representation。第 $i$ 个 anchor 具有：

- $K$ 个局部 offsets：$\mathbf o_i\in\mathbb R^{K\times3}$；
- 空间 anchor feature：$\mathbf F_i\in\mathbb R^{C_F}$；
- 覆盖 $T$ 个视频帧的 time-dependent features：$\mathbf T_i\in\mathbb R^{T\times C_T}$；
- 用于区分 static/dynamic anchor 的时间 mask 参数 $d_i$。

在时刻 $t$，共享 MLP 联合读取 $\mathbf F_i$ 和 $\mathbf T_{i,t}$，预测每个局部 Gaussian 的 color、rotation、scale、opacity 及 time-varying motion parameters。

### 1. 为什么即时 opacity 不能直接做 importance

普通 3DGS 每个 Gaussian 显式存储 opacity，可以随时查询。Anchor-based representation 不同：Gaussian opacity 由 MLP 根据 anchor feature 与当前 view 临时解码，而且只有落入当前 camera frustum 的 anchor 才会 spawn。

如果只查看一次 iteration 的 opacity：

- 当前视角看不见的 anchor 没有被解码；
- 某个 Gaussian 可能在其他视角或其他时间非常重要；
- 用单帧 opacity 判断会把“暂时未观测”误判为“长期无贡献”。

ACA-GS 因此在一次 relocation interval $T_R$ 内累积第 $i$ 个 anchor、第 $k$ 个 Neural Gaussian 的 view-dependent opacity：

$$
\mathcal I_{i,k}
=\sum_{t=1}^{T_R}\alpha_{i,k}^{(t)}(v_t).
$$

$v_t$ 是 iteration $t$ 抽到的训练视角，$\alpha_{i,k}^{(t)}$ 是当时解码的 opacity。每次 relocation 后清零重新累计，使下一周期只反映近期训练状态。

直觉上，跨多个视角与时间反复保持高 opacity 的 Gaussian 更可能真实参与了动态场景表示。但这个分数仍是 opacity proxy，而不是严格 rendering contribution：它没有显式乘 projected area、pixel coverage、front-to-back transmittance 或 image residual。

### 2. Adaptive Anchor Cardinality：回收而非增殖

AAC 每次执行两步：

1. **Importance-driven deactivation**：$\mathcal I_{i,k}<\tau$ 的 Gaussians 标记为 inactive/dead；每次最多移动总数的 $\rho\%$，防止结构剧烈变化。
2. **Sampling-based relocation**：对每个 dead Gaussian，从 alive set 按 importance-proportional probability 采样一个 parent。它继承 parent 的属性与 anchor membership，并在 parent offset 附近重新初始化。

默认参数为：

$$
\tau=0.005,\qquad \rho=20\%.
$$

新 offset 为：

$$
\mathbf o_{\mathrm{new}}
=\mathbf o_{\mathrm{parent}}
+|\mathbf o_{\mathrm{parent}}|\odot\boldsymbol\epsilon,
\qquad
\boldsymbol\epsilon\sim\mathcal N(0,\delta^2I),
$$

其中 $\delta=0.05$。绝对值保证扰动尺度非负，Hadamard product 让每个轴的扰动与 parent offset magnitude 成比例。

因为重要 Gaussian 更可能被抽作 parent，细节或复杂运动区域逐渐聚集更多 Neural Gaussians；平滑区域的无效 primitives 被回收。总 Gaussian slot population 基本保持不变，但各 anchor 的有效 cardinality 变得不均匀。

这与标准 densification 的区别是：densification 通过增加 anchors/parameters 扩容，AAC 则在固定预算内重分配已有 slots。

### 3. Cardinality gating：可变有效数量、固定解码形状

直接允许每个 anchor 具有不同张量长度，会使 MLP batching 和参数存储复杂化。论文仍为每个 anchor 设定最大 $K_{\max}$，共享 MLP 密集预测所有候选 Gaussian attributes，再使用 binary gate：

$$
g_{i,k}\in\{0,1\},
\qquad
\tilde\alpha_{i,k}=g_{i,k}\alpha_{i,k}.
$$

$g_{i,k}=0$ 的 Gaussian 在 rasterization 前被排除。这样 cardinality 的变化落在 gate 上，decoder 结构仍是规则张量。

这里需要区分三种收益：

- **序列化存储**：训练结束后 inactive offsets/attributes 可真正 prune；
- **rasterization**：inactive Gaussian 不进入渲染，可提高 FPS；
- **MLP decode compute**：论文明确说 attributes 仍按固定上限密集预测，因此这部分并未完全变成 conditional compute。

### 4. Adaptive Anchor Feature Masking：两级而非任意逐通道容量

每个 anchor feature 被拆成：

$$
\mathbf F_i
=\operatorname{concat}
(\mathbf F_i^{\mathrm{base}},\,M_i\mathbf F_i^{\mathrm{adapt}}).
$$

$\mathbf F^{\mathrm{base}}$ 始终启用，作为稳定的最低表示容量；$\mathbf F^{\mathrm{adapt}}$ 可以被 mask。Binary mask 通过 straight-through estimator（STE）学习：

$$
M_i=operatorname{sg}
(\mathbf1[\sigma(m_i)>\gamma]-\sigma(m_i))
+\sigma(m_i).
$$

`sg`（stop-gradient）使 forward 使用硬阈值 $0/1$，backward 仍通过 sigmoid surrogate 传递梯度。Mask sparsity loss 为：

$$
\mathcal L_M=\frac1N\sum_{i=1}^{N}\sigma(m_i),
$$

它推动 $M_i$ 关闭 adaptive block。

论文称其为 feature channel masking，但公式中的 $M_i$ 是**每个 anchor 一个标量**，乘在整个 $\mathbf F_i^{\mathrm{adapt}}$ block 上。因此当前设计实际提供两档容量：

- 只使用 $C_{base}$ 个 channels；
- 使用 $C_{base}+C_{adapt}$ 个 channels。

它不是为每个 anchor 学习任意数量或任意组合的逐 channel mask。这个二级结构降低了索引与熵编码复杂度，也比全通道独立 mask 更稳定，但标题中的“modulates feature channels”容易让人误以为容量是连续细粒度的。

### 5. Spatio-temporal interference 与条件正则

若所有 anchor 都被强迫关闭 $\mathbf F^{adapt}$，dynamic anchors 可能让 time-dependent feature $\mathbf T_{i,t}$ 同时编码空间细节和运动。结果是 temporal capacity 被空间外观占用，反而损害动态建模和压缩。

作者使用时间 mask 参数 $d_i$ 构造：

$$
\mathcal L_{CR}
=\frac1N\sum_{i=1}^{N}
\sigma(d_i)(1-\sigma(m_i)).
$$

当 $d_i$ 表明 anchor 具有较强动态需求时，若 $m_i$ 很低、试图关闭 adaptive feature，loss 会变大；静态 anchor 的该约束较弱，可以更激进地压缩。

换句话说：

- $\mathcal L_M$ 全局鼓励少用 feature；
- $\mathcal L_{CR}$ 为运动关键区域保留更多 feature；
- base block 为所有 anchors 保留最低安全容量。

### 6. 联合训练目标与 schedule

最终目标为：

$$
\mathcal L
=\mathcal L_{base}
+\lambda_M\mathcal L_M
+\lambda_{CR}\mathcal L_{CR},
$$

其中 $\mathcal L_{base}$ 沿用 GIFStream 的 rendering loss、compression entropy loss 和其他 regularization。

训练策略：

- AAFM 从训练开始启用；
- 调整 $\lambda_M$，使最终 masking ratio 约为 60%；
- AAC 等 anchor densification 稳定后，从 iteration 3000 开始，每 500 iterations 执行一次；
- 训练结束后 post-hoc prune inactive Neural Gaussians 与 masked anchor features；
- 再使用 GIFStream 的 end-to-end entropy coding 得到最终文件。

## 实验关键数据

### 实验设置

论文使用三个真实动态多视角数据集：

- **MPEG**：Bartender 与 Cinema，不降低图像分辨率；
- **Panoptic Sports**：动态人体/体育场景；
- **N3DV**：按先前工作将图像下采样到 0.5 倍。

指标为 PSNR↑、SSIM↑、LPIPS↓ 与 storage size（MB）↓。N3DV 使用 LPIPS-AlexNet，其他数据使用 LPIPS-VGG，因此不同数据集的 LPIPS 数字不能横向比较。

论文没有报告训练 GPU、训练 wall-clock、峰值 VRAM、编码/解码时间或压缩文件各字段占比。Panoptic Sports 的 GIFStream 配置未找到，因此论文直接引用其 paper-reported results，而不是统一环境复跑。

### 主实验：与 GIFStream 的直接比较

| Dataset | 方法 | PSNR ↑ | SSIM ↑ | LPIPS ↓ | Size ↓ |
| --- | --- | ---: | ---: | ---: | ---: |
| MPEG | GIFStream | 29.89 | **0.900** | **0.223** | 5.4 MB |
| MPEG | **ACA-GS** | **29.92** | 0.898 | 0.228 | **3.5 MB** |
| Panoptic Sports | GIFStream | **29.50** | **0.931** | **0.114** | 12.6 MB |
| Panoptic Sports | **ACA-GS** | 29.30 | 0.922 | 0.128 | **7.3 MB** |
| N3DV | GIFStream | **31.75** | 0.938 | **0.051** | 10.0 MB |
| N3DV | **ACA-GS** | 31.73 | **0.940** | 0.058 | **6.3 MB** |

存储缩减为：

- MPEG：5.4 → 3.5 MB，减少 **35.2%**，相当于 1.54× 更紧凑；
- Panoptic Sports：12.6 → 7.3 MB，减少 **42.1%**，相当于 1.73×；
- N3DV：10.0 → 6.3 MB，减少 **37.0%**，相当于 1.59×。

质量权衡并非完全无损：

- MPEG 的 PSNR +0.03 dB，但 SSIM -0.002、LPIPS +0.005；
- Panoptic 的 PSNR -0.20 dB、SSIM -0.009、LPIPS +0.014；
- N3DV 的 PSNR -0.02 dB、SSIM +0.002、LPIPS +0.007。

因此最稳妥的结论是：**ACA-GS 在 perceptual quality 大体相近的条件下换取 35%–42% 存储缩减**。论文摘要的 “without degrading visual quality” 应理解为视觉质量仍具竞争力，而不是每个指标均无下降。

### 与其他动态 3DGS 的整体位置

在 MPEG 上，ACA-GS 以 3.5 MB 获得 29.92 dB，是表中最高 PSNR 与最小 size；但 GIFStream SSIM/LPIPS 更优。在 Panoptic Sports 上，ACA-GS 的 7.3 MB 最小，但 GIFStream 的全部三项质量指标更好。在 N3DV 上，ACA-GS 仍最小，PSNR 与 GIFStream 接近，但 LPIPS 落后。

相对未压缩或弱压缩方法，size 差距很大：

- Panoptic Dynamic 3DGS 为 2083.8 MB，4DGS 为 973.8 MB；
- N3DV 4DGS 为 202 MB，STG 为 200 MB；
- ACA-GS 维持 6.3–7.3 MB。

不过这些方法属于不同 representation family，质量、训练成本和功能也不同。更能隔离本文贡献的基线仍是同一 anchor/compression backbone 的 GIFStream。

### 整体架构消融

Table 3 在 MPEG Bartender 上同时比较未压缩结构和 GIFStream compression：

| Compression | AAC | AAFM | PSNR | FPS | # Anchors | Size |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 否 | 否 | 否 | 32.07 | 55 | 111,759 | 248.3 MB |
| 否 | 是 | 否 | **32.30** | 67 | 59,336 | 132.2 MB |
| 否 | 是 | 是 | 32.13 | 71 | **54,828** | 117.6 MB |
| 是 | 否 | 否 | 31.94 | 77 | 111,759 | 5.3 MB |
| 是 | 是 | 否 | **32.12** | 83 | 59,336 | 4.0 MB |
| 是 | 是 | 是 | 32.02 | **84** | **54,828** | **3.5 MB** |

主要结论：

1. AAC 单独将 anchor count 减少 46.9%，PSNR 反而提高 0.23 dB，说明固定 $K=5$ 的基线确实通过过多 anchors 获得局部 Gaussian 数。
2. AAFM 继续减少约 4,508 anchors，并缩减 features，但 PSNR 从 32.30 降到 32.13；它主要贡献 size/FPS，而非 fidelity。
3. 自适应结构与 GIFStream codec 互补：完整 compressed model 比 5.3 MB baseline 少 33.9%，FPS 从 77 提至 84。
4. 最终 3.5 MB 的巨大压缩大部分来自 GIFStream 本身：未压缩完整结构仍为 117.6 MB。ACA-GS 的核心贡献是把同一 codec 的 5.3 MB 再压到 3.5 MB，而不是独立实现从 248 MB 到 3.5 MB 的全部压缩。

### AAC 最大 cardinality

| 设置 | Max cardinality | PSNR | # Gaussians | # Anchors | Size |
| --- | ---: | ---: | ---: | ---: | ---: |
| 固定 | 5 | 32.07 | 558,795 | 111,759 | 248 MB |
| 自适应 | 6 | 31.88 | **196,501** | 58,899 | 130 MB |
| 自适应 | **10** | **32.13** | 250,792 | 54,828 | **118 MB** |
| 自适应 | 14 | 32.02 | 267,225 | **52,905** | 122 MB |

Cardinality 过小使单 anchor 表达不足；过大则让重要 anchors 聚集过多 Gaussians，作者观察到 floaters。$K_{max}=10$ 是本文折中，但“robust generalization across scene scales”只由一个 Bartender 消融表支持，仍需跨数据集验证。

### AAFM channel capacity

N3DV Flame Steak 上：

| Total channels | Base / Adaptive | PSNR | LPIPS | Size |
| ---: | ---: | ---: | ---: | ---: |
| 24 | 12 / 12 | 32.96 | 0.044 | **5.34 MB** |
| **48** | **24 / 24** | **33.64** | 0.043 | 6.15 MB |
| 64 | 32 / 32 | 33.57 | **0.041** | 6.77 MB |

48 channels 相比 24 channels 明显改善 PSNR；继续加到 64 没有 PSNR 收益，但 LPIPS 略好。因此 48 是 PSNR-size compromise，并非所有指标上的唯一最优点。

### Mask strength 与超参数

$\lambda_M$ 从 $3\times10^{-3}$ 提高到 $3\times10^{-2}$ 时，masking ratio 从 32% 增至 89%，size 从 3.8 MB 降到 3.0 MB，但 PSNR 从 32.07 降到 31.50。作者采用 $8\times10^{-3}$，得到约 61% mask、3.5 MB 和 32.02 dB。

Table 7 对 $\lambda_{CR}$、STE threshold $\gamma$、importance threshold $\tau$ 与 relocation cap $\rho$ 做单因素扫描。给定范围内 size 只变化 3.4–3.6 MB、PSNR 约 31.80–32.03；但实验只在 MPEG Bartender 上，且没有考察参数交互或随机重定位的方差。

### 关键发现

1. Anchor count、每 anchor Gaussian 数和 feature capacity 分开控制，比只用 anchor densification 更高效。
2. AAC 是主要结构收益来源：大幅减少 anchors，同时在 Bartender 上提高 PSNR/FPS。
3. AAFM 进一步减少存储和少量 anchors，但会带来可见的小幅质量交换。
4. ACA-GS 对 fast/large motion 的 MPEG 数据最有说服力，在最小 size 下保持最高 PSNR。
5. Panoptic 与 N3DV 的结果支持“comparable quality”，不支持“所有质量指标不下降”。
6. 完整压缩依赖 GIFStream entropy pipeline；ACA-GS 更像 adaptive front-end，而不是独立 codec。

## 亮点与洞察

### 论文亮点

- **问题拆分准确**：复杂区域需要更多 local Gaussians 不等于需要更多 anchors；动态运动自由度和空间细节自由度也不是同一资源。
- **预算守恒式 relocation**：回收 dead primitives，而非继续增加总 slots，直接面向 fixed-budget rate–distortion。
- **跨视角累积适配 anchor opacity**：认识到 view-dependent decoder 下 instantaneous opacity 不能直接照搬 vanilla 3DGS pruning。
- **Gating 保留规则张量**：有效 cardinality 可变，同时避免 per-cardinality decoder 和不规则 batch。
- **为动态区域设计条件压缩**：$\mathcal L_{CR}$ 不让全局 sparsity objective 盲目伤害 motion-critical anchors。
- **与既有 codec 正交**：未压缩和 GIFStream-compressed 两套消融证明 adaptive allocation 能叠加在 entropy coding 上。
- **实验给出 size、FPS、anchor/Gaussian 数**：比只报 PSNR 更能说明压缩机制。

### 我的洞察

- **个人分析：AAC 是 anchor 内部的 MCMC-style budget recycling。** 它与 3DGS-MCMC relocation 思想相近，但移动的不是独立 Gaussian 的全局位置，而是 Neural Gaussian slot 的 anchor membership 与 local offset。
- **个人分析：重要区域为何得到更少 anchors、更多 Gaussians。** 对精细静态区域，多个 Neural Gaussians 可以共享一个 anchor feature；对复杂运动区域，仍需要更多 anchors 提供不同 deformation trajectories。这种二维资源图比单一 density map 更贴近动态场景本质。
- **个人分析：AAFM 实际是 two-tier feature width。** Base/adaptive 二分让实现和压缩简单，却没有真正学习 24、25、…、48 这类连续 channel counts；后续可以用 group-wise masks 获得更平滑的 rate allocation。
- **个人分析：结构压缩改变了后续 codec 的统计分布。** 更少 anchors、更集中 Gaussian cardinality 和大量全零 adaptive blocks会降低熵，因而 ACA-GS 的收益不只是删参数，也可能让 GIFStream context model 更容易编码。
- **个人分析：PSNR 提升不一定证明“把 Gaussian 移到了复杂区域”。** AAC 同时改变 anchor densification trajectory、Gaussian count 和 optimization dynamics；需要与同 Gaussian/anchor budget 的 error-guided allocation 做对照，才能隔离 importance relocation 的优势。
- **个人分析：动态保护项使用已有 time mask 是一种便宜的 conditional prior。** 无需显式 optical flow 或 motion magnitude，直接复用 representation 内部的 dynamic indicator 决定压缩强度，这是很实用的系统设计。

## 局限与展望

### 作者明确/结论中给出的边界

- 未来需要扩展到 long video sequences，并增强 inter-frame consistency；
- 可结合 hierarchical anchor representation，在不同空间尺度进一步调节复杂度；
- 最大 cardinality 过高会造成 Gaussian over-concentration 与 floater artifacts；
- 过强 AAFM sparsity 会明显降低重建质量。

### 独立分析

- **官方代码尚未公开**：无法核对 GIFStream fork、压缩 bitstream、pruning 细节、随机采样、FPS 环境和复现命令。
- **Opacity importance 不等于实际贡献**：未乘 visibility count、projected area、transmittance 或 residual；高 opacity 但长期被遮挡的 Gaussian 可能被高估。
- **累积而未归一化仍有采样偏差**：更常被训练相机和时间采到的 anchor 天然累积更大 $\mathcal I$；它缓解单视角偏差，但不能严格称为 view-independent。
- **Offset perturbation 依赖 $|\mathbf o_{parent}|$**：若某个轴 offset 接近 0，该轴几乎不扰动；anchor 中心附近的复制可能高度重合。按 Gaussian scale 或 voxel size 扰动会更稳定。
- **随机 relocation 没有多 seed 统计**：主表和超参数表都没有均值/方差，小于 0.1 dB 的变化未必稳定。
- **“Feature Masking”粒度较粗**：每 anchor 一个标量决定整块 adaptive channels 开关，并非逐 channel 自适应。
- **Dense decoding 保留最大 $K$ 开销**：inactive candidates 虽在 rasterization 前剔除，shared MLP 仍密集预测固定上限属性；真实 FLOPs 与 latency 节省没有拆解。
- **后处理 pruning 的部署形式不清楚**：不同 anchors 具有不等 cardinality/feature width 后，实际 GPU kernel 与 bitstream 如何组织未说明。
- **没有训练成本与编码成本**：频繁 importance accumulation、每 500 steps relocation、STE mask 和 entropy training 是否增加 wall-clock/VRAM 未报告。
- **Panoptic baseline 非同环境复跑**：GIFStream 的 Panoptic numbers 来自原论文，训练配置缺失会削弱严格公平性。
- **MPEG 只有两个序列平均**：Bartender/Cinema 支持快速运动结论，但覆盖面仍有限。
- **质量并非无损**：Panoptic 全部感知指标变差，N3DV LPIPS 也变差；需要 rate–distortion Pareto 而非单点 “comparable” 概括。
- **消融集中在单场景**：AAC、mask ratio 和超参数主要在 Bartender 或 Flame Steak 上分析，跨数据集可迁移性没有完整表格。
- **GIFStream 贡献占比很大**：248.3→5.3 MB 来自 backbone codec；ACA-GS 的公平增量是 5.3→3.5 MB。
- **缺少现代强压缩基线的统一复跑**：OMG4D、MEGA、4DGS-1K、Light4GS 等在 related work 中出现，却未进入主表直接比较。

### 建议的后续实验

1. 发布代码、完整 configs、压缩/解压脚本、GPU 型号、训练与编码时间，并验证 bit-exact size。
2. 将 importance 改为 opacity × projected area × transmittance × residual，比较 raw opacity、visibility-normalized opacity 与真实 leave-one-out contribution。
3. 记录每次 relocation 的 source/target、存活率和区域 motion/detail statistics，验证容量确实流向预期区域。
4. 对 $\mathbf o_{parent}$、Gaussian scale、anchor voxel size 三种 perturbation scale 做稳定性比较。
5. 在 5–10 个 random seeds 下报告 PSNR/LPIPS/size/FPS 的均值和方差。
6. 设计 group-wise AAFM，例如每 4 或 8 channels 一个 gate，比较 two-tier、group-wise 与 per-channel 的 rate–distortion 和 kernel overhead。
7. 分别测 decoder MLP time、Gaussian assembly、sorting/rasterization 和 entropy decode，说明 FPS 提升来自哪里。
8. 在固定 anchor budget、Gaussian budget和总 bits 下，对比 densification、relocation、error-guided allocation 与 MCMC-style recycling。
9. 补充 long sequence、拓扑变化、极快运动和低运动场景，验证条件正则是否真能区分 temporal 与 spatial capacity。
10. 与 OMG4D/MEGA/4DGS-1K 在相同分辨率、LPIPS backbone 和硬件上绘制完整 rate–distortion–FPS 曲线。

## 启发与关联

- **压缩前先修正容量拓扑**：量化/熵编码只能压缩已有参数分布；先把 primitives 和 features 移到真正需要的区域，通常能获得更好的 rate–distortion。
- **Anchor 是多维资源调度器**：空间位置、motion trajectory、local Gaussian count 和 feature width 可以分别控制，而不是把 densification 当作万能操作。
- **训练期规则张量、发布时稀疏化**：使用 gate 保持 batch-friendly training，最后 prune/encode，是兼顾可训练性与部署 compactness 的通用范式。
- **动态信号应保护而非只被压缩**：全局 sparsity 会优先伤害难拟合区域；用 motion indicator 调节 regularization 可迁移到 dynamic NeRF、video codec 和 point-based animation。
- **假设：把 AAC 与 Blur Trap exploration 结合**。Blur Trap 随机 split 让低梯度区域获得容量；AAC 回收长期无贡献 slots。联合后可在固定总预算内完成 exploration、survival 和 relocation。
- **假设：把 AAFM 改为 progressive channel groups**。让简单区使用 24 channels，中等区 32/40，复杂动态区 48，可比当前 24/48 两档更贴近连续复杂度。
- **假设：使用 uncertainty-aware importance**。将 view coverage、motion prediction residual、temporal variance 与 opacity 结合，避免训练采样频率支配 relocation。

## 阅读结论

- **最值得记住的点**：复杂静态区域需要“少 anchors、多 local Gaussians”，复杂运动区域需要“多 anchors、足 feature capacity”；固定 $K/C_F$ 会把两类需求都错误地转化为 anchor densification。
- **最需要怀疑的点**：累积 opacity 是否真能代表跨视角时空贡献，以及所谓 feature-channel adaptivity 是否被每 anchor 单一 block gate 过度包装。
- **最值得复现或继续验证的点**：在固定 bit budget 下，比较 raw-opacity relocation、visibility-normalized contribution、group-wise feature masks，并拆分 decoder、rasterizer 与 codec 的真实速度/存储收益。
